# 역대 기록(Record Book) 4단계 B 설계 — 최다 점수차 역전승

작성: 2026-10-11 · 이전 단계: 1~3단계, 4단계 A(`2026-10-11-record-book-phase4a-design.md`)

## 1. 범위

사용자가 고른 4가지 중 두 번째(4B). 이긴 팀이 경기 중 **뒤졌던 최대 점수차**를 역대 순위로 알린다: 라이브에서는 "큰 열세 중" 패널 줄과 "열세를 뒤집고 리드" 토스트(잠정), 종료 후에는 리포트 줄.
상태기계·로그가 필요 없는 **경기 단위 보드**라 3·4A단계의 연속 구조와 달리 기존 `moment_candidates`(2단계)에 후보 함수 하나를 더하는 방식이다. 시즌 누적(4C)은 별도.

## 2. 정의

- **역전승 점수차** = 이긴 팀이 그 경기에서 가졌던 최대 열세(상대 득점 − 자기 득점의 최댓값). 정규시즌·플레이오프·챔프전 모두, 연장 포함, 전시경기 제외. 한 경기당 이긴 팀 한 행.
- 같은 값이 진 팀 입장에서는 "**리드를 날린 패배**"(진 팀이 가졌던 최대 리드)다. 별도 보드를 만들지 않고 같은 줄의 설명에 "진 팀은 N점 리드를 날림"으로 함께 적는다.
- 점수 경로는 이벤트의 득점(201·207·205·203, 선수 귀속)으로 쌓은 두 팀 점수의 차이를 이벤트 순서(`n`)대로 따라간다. **게이트**는 2단계와 같다: 이벤트 쿼터 득점이 공식 쿼터 점수와 같고 최종 점수가 공식과 같을 때만(`quarters_match_official`).
  통과율은 S16(2010-11) 이후 사실상 100%, 2006~09년은 45%·2009~13년은 73%다(5,689경기 중 5,237경기 통과 — 최종 점수만 본 간이 조사).
- 실측(간이 조사): **29점**(서울 SK, 안양 KGC전 2022-01-09) · 28(원주 DB, 서울 SK전 2017-12-12, 연장) · 26(부산 KT, 서울 SK전 2016-11-13, 연장) · 25(안양 KGC 2015-11-28) · 24(안양 정관장 2026-03-09, 서울 SK 2020-10-30) · 23 여섯 경기. 10위 값 23, 15위 값 21.
  20점 이상 34경기(0.65%), 15점 이상 219경기(4.2%).

## 3. 보드와 DB

- 보드 1개 `tg.comeback.max`(bucket `G`, `subject`=이긴 팀 tcode, `period=""`, `value`=열세 점수). 행 후보 최소 15점, 보관 순위 ≤15(동률 포함, 현재 21점까지).
- 경기 단위 후보라 상태 테이블·로그가 없고 **DDL 변경이 없다**. `record_book.py`의 `moment_candidates`(게이트 1 통과 경기) 안에 `comeback_candidates(g)`를 더하고, 경기 종료 정산(`--gmkeys`)·`--rebuild`·`--verify`가 그대로 처리한다.
  롤백: `DELETE FROM record_entries WHERE board = 'tg.comeback.max'`.

## 4. 웹

새 순수 엔진 `lib/comebackMoments.ts`: `buildComebackMoments(ctx, events, opts, finals?)`. 이벤트의 `home_score`/`away_score`로 두 팀의 "지금까지 최대 열세"를 따라가며 보드 요약(`ctx.boards["tg.comeback.max|G"]`)과 비교한다.
- **임박(near, 패널)**: 한 팀의 최대 열세 M이 **20점 이상**이고 그 팀이 아직 리드를 잡지 못했을 때. `OO 22점 열세 · 뒤집으면 KBL 역대 공동 10위 역전승`(M이 아직 TOP10 밖이면 다음 순위 선까지 몇 점인지). 그 팀이 리드를 잡거나 경기가 끝나면 닫는다.
- **확정(done, 토스트·리포트)**: M이 TOP10(10위 값 이상)인 열세를 뒤집고 **처음 리드를 잡는 이벤트**. 라이브는 잠정(provisional)이라 `…리드 · 이대로 이기면 KBL 신기록(종전 28점)`, 순위가 더 좋아질 때(열세가 더 깊어진 뒤 다시 뒤집을 때)만 다시 알린다.
  종료 경기는 *이긴 팀*의 마지막 리드 탈환 이벤트에서 한 번, 테이블에 이 경기 행이 있을 때(`validated`)만: `서울 SK 29점차 열세를 뒤집은 역전승 KBL 신기록(종전 28점)`, 설명 `안양 KGC는 29점 리드를 날림 · 종전 원주DB(2017-12-12)`.
- 문구는 1단계 문법(`verdictText`, `holdersLine`)을 따르고 리포트·재생·패널·토스트 경로는 `buildAllRecordMoments`가 합치는 기존 길을 그대로 쓴다. 팀 점수를 모르는 이벤트(점수 null)는 건너뛴다.
- `finals`(파이썬 대조용): 이긴 팀 `tg.comeback.max|G|<tcode>|` → 최대 열세(15 이상일 때).

## 5. 알림 빈도·롤아웃

- 확정 알림은 TOP10(23점+)이라 경기당 약 0.2%로 드물고, 임박 줄은 20점 이상 열세를 겪는 경기(약 1~2%)에만 뜬다. 신기록 경신 줄은 매번 뜨지 않는 사건이라 `quiet` 같은 억제가 필요 없다.
- 롤아웃: 파이썬 + 테스트 → 로컬 커밋 → **DB 쓰기 확인 후** `--rebuild`(약 2~8분, DDL 없음, `--verify`) → 웹 → 푸시(푸시 전 `next build` 복사본 점검) → 프로덕션 확인. 옛 웹은 새 보드를 읽지 않으므로 DB가 먼저여도 안전하다.

## 6. 테스트

- 파이썬: 마진 경로(역전·끝까지 앞선 팀은 행 없음·동점/점수 없음 건너뜀·최소 15점 미만 제외·연장 포함·플레이오프 포함), 게이트 탈락 경기는 후보 없음, `moment_candidates`에 합쳐짐; 실데이터 단언(29점 서울 SK 2022-01-09 등, `RECORD_BOOK_SLOW=1`).
- 웹: 임박 열림·닫힘(리드 탈환/경기 끝), 확정(TOP10 안/밖, 라이브 잠정, 종료 경기 validated·마지막 탈환 위치), 순위 개선 때만 재알림, 점수 null 건너뜀, `finals`; 파이썬↔웹 대조(2단계 `momentParity` 픽스처 + 역전승 경기 둘 추가: 29점·연장 28점).

## 7. 열린 값(기본값으로 진행)

임박 시작 20점, 행 후보 최소 15점, "리드를 날린 패배"는 별도 줄 없이 설명에 병기, 대상은 정규시즌·플레이오프 모두. 경기 막판 결승 득점·버저비터·하프타임 대량 열세 같은 시점 기록은 이번 범위 밖.
